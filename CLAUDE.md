# youtube-gt.el - Quick Reference

## Overview

An Emacs package for managing YouTube playlist information in org-mode files. Uses the YouTube Data API v3 to fetch playlist data and generates/updates org-mode tables with video information.

## Key Features

- Fetches playlist data via YouTube Data API v3
- Channel URL support (`@username` format) to fetch all uploads
- Generates formatted org-mode tables with video metadata
- Preserves manual notes across updates
- Keeps annotated rows that leave the fetch, with the index they had
- Five directive filters: `:offset`, `:newest`, `:min-length`,
  `:since`, `:match`
- Stops paginating early for `:newest` / `:since`, so a handful of
  videos from a 20k-video channel costs ~2 requests, not ~800
- UTF-8 support for international characters

## Core Concepts

### Directive Syntax

```org
# Playlist URL
#+YOUTUBE-GT_UPDATE: https://www.youtube.com/playlist?list=PLAYLIST_ID
#+YOUTUBE-GT_UPDATE: https://www.youtube.com/playlist?list=PLAYLIST_ID:offset=50

# Channel URL (fetches all uploads)
#+YOUTUBE-GT_UPDATE: https://www.youtube.com/@username/videos
#+YOUTUBE-GT_UPDATE: https://www.youtube.com/@username/videos:offset=100

# Filters combine in any order; values attach with `=', no space
#+YOUTUBE-GT_UPDATE: https://www.youtube.com/@CBCNews/videos :since=20260101 :match="About That"
#+YOUTUBE-GT_UPDATE: https://www.youtube.com/@CBCNews/videos :newest=20
```

### Worked Example: One Segment of a Large Channel

`@CBCNews` has about 20,000 videos. To retrieve the recent "About
That" segments, the three possible directives differ by two orders of
magnitude in cost:

```org
# ~800 requests: fetches all 20k videos, then filters
#+YOUTUBE-GT_UPDATE: https://www.youtube.com/@CBCNews/videos :match="About That"

# ~800 requests on a manually ordered playlist, far fewer on a channel:
# stops at the first page that predates the cutoff
#+YOUTUBE-GT_UPDATE: https://www.youtube.com/@CBCNews/videos :since=20260101 :match="About That"

# A few requests: stops as soon as 20 matches are found
#+YOUTUBE-GT_UPDATE: https://www.youtube.com/@CBCNews/videos :newest=20 :match="About That"
```

The third is the one to use on a large channel. `:newest` limits the
number of videos fetched by the number of rows requested rather than
by the size of the playlist: pagination stops at 20 matches regardless
of how many videos remain unfetched. The limitation follows from
fetching newest-first: the fewer videos match, the more pages must be
fetched to find 20 of them, so a segment that aired twice in 2019
still requires fetching most of the playlist.

`:since` limits fetching by date and `:newest` by count; combining
them stops at whichever condition is met first.

### Directive Parameters

Declared in `youtube-gt--param-specs` as (NAME . TYPE); adding one is
a line there plus a branch in `youtube-gt--param-value-regexp` and
`youtube-gt--param-value` if the type is new.

| Param | Type | Meaning |
|-------|------|---------|
| `:offset=N` | integer | Skip the N oldest videos |
| `:newest=N` | integer | Keep only the N newest (highest indices) |
| `:min-length=N` | integer | Keep videos of at least N minutes |
| `:since=DATE` | date | Keep videos published on/after DATE (`YYYYMMDD` or `YYYY-MM-DD`) |
| `:match=REGEXP` | regexp | Keep videos whose title matches, case-insensitively; quote if it has spaces |

Semantics worth remembering:

- Index 0 is the **oldest** video, so `:newest` yields the highest
  indices, never a fresh 0..N-1 numbering.
- Indices are assigned **before** content filtering, so gaps show
  where a filtered video sits in the playlist.
- `:newest` is applied **last**, to whatever survived the other
  filters — "the N newest that match", not "the matches among the N
  newest".
- `:offset` + `:newest` is rejected (`user-error`): they count from
  opposite ends.
- Unknown duration fails `:min-length`; unknown publication date
  fails `:since`. Videos with missing data are excluded rather than
  assumed to pass.
- Names are matched **case-sensitively** and in full.
- **Any text after the URL that is not a recognized parameter is
  refused** with a `user-error` naming it; no API call is made.
  `youtube-gt--url-token-p` enforces this: once every recognized
  parameter has been stripped, the remainder must be one token with no
  colon outside its `://` scheme. A surviving colon means a
  misspelling, wrong case, missing value, or unknown name. Ignoring
  such text would produce a table for the whole unfiltered playlist,
  which on a 20k-video channel is both wrong and slow.
- `youtube-gt--parse-directive-args` returns `(URL PARAMS)` on success
  and `(nil LEFTOVER)` on failure, so the error can quote the text at
  fault.

### Early-Stopping Pagination

`youtube-gt--fetch-all-videos` fetches pages newest-first and returns
`(TOTAL . VIDEOS)`, VIDEOS oldest-first. Its `keep-p`, `limit`, and
`stop-page-p` arguments are **pure optimizations**: they only stop
pagination sooner. All filtering that determines the table contents is
redone in `youtube-gt--update-at-point`, so a stubbed fetch still
produces correct output.

- `TOTAL` is an exact count when every page was fetched, and the
  API-reported total when fetching stopped early (that number can be
  inaccurate on playlists with private or deleted videos).
- Absolute index of the first fetched video is `TOTAL - (length VIDEOS)`,
  floored at 0.
- `:since` early-stops **only** on uploads playlists (ID prefix `UU`,
  see `youtube-gt--uploads-playlist-p`). A manually ordered playlist can
  list an old video before a recent one, so every page of one is
  fetched.

### Generated Table Format

| Column | Content | Description |
|--------|---------|-------------|
| 1 | Index | Video position (0-based, oldest first) |
| 2 | Note1 | User manual note (preserved on update) |
| 3 | Note2 | User manual note (preserved on update) |
| 4 | Duration | Video length (HH:MM:SS or MM:SS) |
| 5 | Published | Publication date (YYYY-MM-DD) |
| 6 | URL | Org link `[[url][video-id]]` |
| 7 | Title | Video title |

## Key Functions

### Public API

- `youtube-gt-update-all` - Update all playlist tables in buffer (interactive)
- `youtube-gt-update-at-point` - Update only the directive at point (interactive)

### Internal Functions

| Function | Purpose |
|----------|---------|
| `youtube-gt--get-api-key` | Get API key from authinfo or custom var |
| `youtube-gt--extract-playlist-id` | Extract playlist ID from URL |
| `youtube-gt--extract-channel-handle` | Extract @handle from channel URL |
| `youtube-gt--fetch-uploads-playlist-id` | Get uploads playlist ID for a channel |
| `youtube-gt--uploads-playlist-p` | Is this ID a channel's uploads playlist (`UU` prefix)? |
| `youtube-gt--chunk-list` | Split list into chunks (for API batching) |
| `youtube-gt--fetch-durations` | Duration alist for a batch of video IDs |
| `youtube-gt--videos-from-items` | Parse one page of items into video alists |
| `youtube-gt--fetch-all-videos` | Paginate a playlist; returns `(TOTAL . VIDEOS)` |
| `youtube-gt--stop-page-function` | Page predicate that ends a `:since` fetch early |
| `youtube-gt--parse-directive-args` | Split directive body into (URL PARAMS) |
| `youtube-gt--strip-trailing-param` | Remove one trailing `:name=value` |
| `youtube-gt--param-value-regexp` | Value regexp for a parameter type |
| `youtube-gt--param-value` | Validate/convert a captured parameter value |
| `youtube-gt--normalize-date` | `YYYYMMDD`/`YYYY-MM-DD` → `YYYY-MM-DD`, or nil |
| `youtube-gt--video-keep-p` | Does a video pass every content filter? |
| `youtube-gt--update-at-point` | Update table at current directive |
| `youtube-gt--merge-rows` | Merge old/new rows preserving notes, sorted by index |
| `youtube-gt--sort-rows` | Order rows by index (non-numeric last) |
| `youtube-gt--parse-table` | Parse existing org table |
| `youtube-gt--generate-table-string` | Generate org table from rows |

### Data Structures

**Video alist:**
```elisp
'((id . "VIDEO_ID")
  (title . "Video Title")
  (duration . "PT1H2M3S")   ; ISO 8601 format
  (published . "2024-01-15")
  (url . "https://www.youtube.com/watch?v=VIDEO_ID"))
```

**Table Row alist:**
```elisp
'((index . "0")
  (note1 . "")
  (note2 . "")
  (duration . "1:02:03")
  (published . "2024-01-15")
  (url . "[[https://...][VIDEO_ID]]")
  (video-id . "VIDEO_ID")
  (title . "Video Title"))
```

## Configuration

```elisp
;; API key (or use authinfo - preferred)
(setq youtube-gt-api-key "YOUR-KEY")

;; Max results per API request
(setq youtube-gt-max-results 50)

;; Authinfo host/user for key lookup
(setq youtube-gt-host-key "youtube.com")
(setq youtube-gt-user-name "dmg")

;; Org-mode directive (default: "#+YOUTUBE-GT_UPDATE")
(setq youtube-gt-directive "#+YOUTUBE-GT_UPDATE")
```

## Testing

```bash

make check       # compile + lint + checkdoc + check-declare + test
make check-ci    # the above under every Emacs in the CI matrix
make test-live   # opt-in; spends real API quota
```

**Run `make clean` before `make test`** if anything compiled earlier in
the session: `require` prefers a stale `youtube-gt.elc` over your
edits, and the failures look like real bugs in new code.

Offline tests stub `youtube-gt--fetch-all-videos`, whose return shape
is `(TOTAL . VIDEOS)` — see `youtube-gt-test--fetch-result`. Tests
that need to observe pagination stub `youtube-gt--fetch-json` instead
via `youtube-gt-test--paged-stub`, which counts the pages it served.

## Common Tasks

### Adding a new table column
1. Update `youtube-gt--video-to-row` to add new field
2. Update `youtube-gt--row-to-string` format string
3. Update `youtube-gt--parse-table-row` to parse the column
4. Update documentation in README.md

### Modifying API requests
- `youtube-gt--fetch-playlist-items` - playlist items endpoint
- `youtube-gt--fetch-video-details` - video details endpoint
- `youtube-gt--fetch-uploads-playlist-id` - channels endpoint (for @handle lookup)
- `youtube-gt--api-url` - URL construction

Cost model: 50 videos per `playlistItems` call plus one
`videos` call for that page's durations — about one request (and one
quota unit) per 25 videos. Durations are fetched per page rather than
in one batch at the end, which is what lets pagination stop early.

### Adding a directive parameter
1. Add `(NAME . TYPE)` to `youtube-gt--param-specs`
2. If TYPE is new, extend `youtube-gt--param-value-regexp` (capture in
   group 1, or group 2 for a second alternation branch) and
   `youtube-gt--param-value` (return nil to reject the value)
3. Read it in `youtube-gt--update-at-point`; put content filtering in
   `youtube-gt--video-keep-p` so the fetch-side optimization and the
   post-fetch filter stay in agreement
4. Add it to the progress message's `active` list
5. Document in `readme.org` (run `make info`) and here

### Changing merge behavior
- `youtube-gt--merge-rows` handles the logic for:
  - Preserving notes from old rows
  - Keeping annotated rows that left the fetch, with the index they
    already carried (fetched rows always win the index they were just
    assigned; a preserved index can go stale or collide)
  - Dropping unannotated rows that left the fetch
  - Ordering the result by index via `youtube-gt--sort-rows`
- Legacy tables may hold an `NA` index from before indices were
  preserved; those still parse and sort to the end.
