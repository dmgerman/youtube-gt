An Emacs package for managing YouTube playlists in org-mode
files.

Youtube is full of interesting videos and playlists, but youtube does not make it easy to keep track of what you are watching. And it does not make it easy to query a given playlist.

For example, I like watching CBC's "About That" hosted by Andrew Change. videos. Unfortunately he does not have a specific playlist and worse, the entire playlist of CBC News is 20k videos.

You add the following line to a youtube file. It indicates the address of the playlist, a regular expression that the title must match (in this case "About That", and the maximum number of videos to download (newest 10 in this case).
There are other query parameters (see documentation below).

#+begin_example
,#+YOUTUBE-GT_UPDATE: https://www.youtube.com/@CBCNews/videos  :match="About That"  :newest=10
#+end_example

Then you run the command: ~youtube-gt-update-all~ then it add below a list of videos that match the :match and :newest expressions. The columns are: number of video in the playlist,
user column, user column, length, date of publication, link, and title.

The second and third column are for you to make notes. Rows with info in those columns will be left untouched. that way you can keep track of which videos you have watched
while allowing you to update the playlist.

* Features

- Turn any YouTube playlist or channel URL into an org-mode table that
  refreshes with a single command.
- Two update commands: buffer-wide (=youtube-gt-update-all=) or just
  the single playlist at point (=youtube-gt-update-at-point=).
- Columns 2 and 3 are yours: use them for =watched=, =to-review=,
  ratings, priorities, running commentary --- whatever fits your
  workflow.  Annotations survive every update.
- A row you annotated remains in the table even after the video is no
  longer fetched --- removed from the playlist, or excluded by a later
  change to a filter.  It keeps the index it already had and its
  position in the table, so annotations are never silently lost.
  Unannotated rows that are no longer fetched are removed, so the
  table does not accumulate obsolete rows.
- Per-directive filters: =:offset=N= (skip the first N videos),
  =:newest=N= (keep only the N newest), =:min-length=N= (keep only
  videos of at least N minutes), =:since=DATE= (keep only videos
  published on or after DATE), and =:match=REGEXP= (keep only videos
  whose title matches).  Combine them in any order; malformed forms
  are rejected before any API call.
- =:newest= and =:since= stop fetching early, so retrieving a few
  videos from a 20,000-video channel costs about two requests instead
  of about 800.
- Works uniformly on individual playlists and on whole channels
  (=@handle= URLs are resolved to the channel's uploads playlist).

* Installation

** 1. Get a YouTube API Key

1. Go to [[https://console.developers.google.com/][Google Cloud Console]]
2. Create a new project or select an existing one
3. Enable the *YouTube Data API v3*
4. Create credentials (API key)
5. Copy your API key

** 2. Install the Package

Place =youtube-gt.el= in your Emacs load path, then add to your init file:

#+begin_src elisp
(require 'youtube-gt)
#+end_src

** 3. Configure API Key

Two options for providing the API key:

*Option A: Using authinfo (recommended for security)*

Add to your =~/.authinfo.gpg= file:

#+begin_example
machine youtube.com login dmg password YOUR-API-KEY-HERE
#+end_example

The module reads the key from authinfo when needed.

*Option B: Using Emacs customization*

Set the key in your init file:

#+begin_src elisp
(setq youtube-gt-api-key "YOUR-API-KEY-HERE")
#+end_src

Or set it interactively:

#+begin_example
M-x customize-variable RET youtube-gt-api-key RET
#+end_example

* Usage

** 1. Add Playlist References

In an org-mode file, add a =#+YOUTUBE-GT_UPDATE:= directive with a
playlist URL or channel URL:

*Playlist URL:*

#+begin_src org
,* My Playlist

,#+YOUTUBE-GT_UPDATE: https://www.youtube.com/playlist?list=PLPdNX2arS9MYUGoIp0qogtHZ3fXu46GQt
#+end_src

*Channel URL (all uploads):*

#+begin_src org
,* Channel Videos

,#+YOUTUBE-GT_UPDATE: https://www.youtube.com/@mynameisandong/videos
#+end_src

This fetches all uploaded videos from the channel's uploads playlist.

*Optional parameters*

Append =:name=value= parameters directly to the URL (or after a
space).  Five parameters are recognized:

- =:offset=N= — skip the first =N= videos from the playlist and start
  the index at =N=.
- =:newest=N= — keep only the =N= newest videos (the =N= highest
  indices).  Cannot be combined with =:offset=, which counts from the
  opposite end.
- =:min-length=N= — keep only videos whose duration is at least =N=
  minutes.  Videos with unknown duration are excluded.
- =:since=DATE= — keep only videos published on =DATE= or later.
  =DATE= is written =YYYYMMDD= or =YYYY-MM-DD=.  Videos with an
  unknown publication date are excluded.
- =:match=REGEXP= — keep only videos whose title matches =REGEXP=, an
  Emacs regular expression matched case-insensitively.  Quote the
  value (=:match="About That"=) whenever it contains spaces; a value
  with no spaces or quotes may be written bare (=:match=National=).

Filtered videos keep their original position as their index, so gaps
in the index column reflect where a video sits in the underlying
playlist.  Index 0 is the *oldest* video; =:newest= therefore yields
the highest indices, not a fresh numbering from zero.

The filters compose: =:newest= is applied last, to whatever survived
the others.  So =:newest=10 :match="About That"= means "the 10 newest
videos whose title matches", not "the videos among the 10 newest that
match".

Parameters can be combined in any order:

#+begin_src org
,* Recent long videos (skip first 100, keep >= 30 minutes)

,#+YOUTUBE-GT_UPDATE: https://www.youtube.com/playlist?list=PLPdNX2arS9MYUGoIp0qogtHZ3fXu46GQt:offset=100:min-length=30

,* One segment of a news channel, this year only

,#+YOUTUBE-GT_UPDATE: https://www.youtube.com/@CBCNews/videos :since=20260101 :match="About That"

,* The 20 most recent uploads of a very large channel

,#+YOUTUBE-GT_UPDATE: https://www.youtube.com/@CBCNews/videos :newest=20

,* The 20 most recent "About That" segments

,#+YOUTUBE-GT_UPDATE: https://www.youtube.com/@CBCNews/videos :newest=20 :match="About That"
#+end_src

That last directive is the main use of =:newest=.  =@CBCNews= has
about 20,000 videos, and the three ways of requesting one recurring
segment differ by two orders of magnitude in cost:

| Directive                    | Requests | Why                                        |
|------------------------------+----------+--------------------------------------------|
| =:match="About That"=        | ~800     | Fetches all 20,000 videos, then filters    |
| =:since=20260101 :match=...= | few      | Stops at the first page predating the date |
| =:newest=20 :match=...=      | few      | Stops once 20 matches have been found      |

=:newest= limits the number of videos fetched by the number of rows
requested rather than by the size of the playlist: pagination stops at
20 matches regardless of how many videos remain unfetched.  =:since=
limits it by date instead, and combining the two stops at whichever
condition is met first.

The limitation follows from fetching newest-first: the fewer videos
match, the more pages must be fetched to find 20 of them.  A segment
that aired twice in 2019 still requires fetching most of the playlist.
Add =:since= to bound how far back the search goes.

*Fetching cost*

Videos arrive 50 per request, and durations for those 50 cost one
more request --- roughly one request per 25 videos, each costing one
unit of the 10,000-unit daily API quota.  Fetching a 20,000-video
channel in full is therefore about 800 requests.  That is slow rather
than expensive: it stays well inside the daily quota, but takes a
while, and Emacs is blocked for the duration.

=:newest= and =:since= reduce the number of requests.  Pages arrive
newest-first, so fetching stops as soon as =:newest= has enough
videos, or as soon as a whole page predates =:since=.  =:newest=20= on
that same channel costs about two requests.  Two limitations:

- =:newest= combined with a =:match= that few videos satisfy may still
  fetch most of the playlist before finding =N= matches.
- Early stopping on =:since= applies only to channel uploads, which
  are always in date order.  A manually ordered playlist can list an
  old video before a recent one, so every page of one is fetched.

When fetching stops early, absolute indices come from the playlist
size the API reports, which can be off by a few on playlists
containing deleted or private videos.  Fetching in full counts
exactly.

Parameter values must use =:name=value= exactly (no space between
=:name= and the value).  Whitespace before the =:= is allowed.
Names are matched case-sensitively and in full.

*Anything after the URL that is not a recognized parameter is
refused*: the directive signals a =user-error= naming the text it
could not interpret, and no API call is made.  Nothing is ever
silently ignored, because ignoring a filter would quietly produce a
table for the whole unfiltered playlist.  Refused forms include:

| Directive text      | Why                              |
|---------------------+----------------------------------|
| =:offset 0=         | Space instead of ~=~             |
| =:min-length=abc=   | Value is not an integer          |
| =:since=20261301=   | Month 13 is not a date           |
| =:match="About=     | Unbalanced quote                 |
| =:match="[unclosed"= | Invalid regexp                  |
| =:offst=5=          | Misspelled name                  |
| =:Offset=5=         | Wrong case                       |
| =:newest=           | Name with no value               |
| =:foo=1=            | Unknown name                     |
| =URL junk=          | Trailing text                    |
| =:offset=1 :newest=5= | Contradictory: opposite ends   |

** 2. Generate/Update Tables

Two interactive commands are available:

- =M-x youtube-gt-update-all= — update every =#+YOUTUBE-GT_UPDATE:=
  directive in the current buffer.
- =M-x youtube-gt-update-at-point= — update only the single directive
  associated with point.  Two positions are recognized:
  1. Point is on the =#+YOUTUBE-GT_UPDATE:= line itself.
  2. Point is anywhere inside a table whose immediately-preceding
     line is a =#+YOUTUBE-GT_UPDATE:= directive.

  Any other position, or a table not directly bound to a directive
  (e.g. a blank line intervenes), signals a =user-error=.  The
  command does not search backward across unrelated content, so
  editing a stray region in the buffer never triggers the wrong
  playlist's update.  Useful in buffers with many playlists where a
  full-buffer update would be slow or burn extra API quota.

Either command generates a table below its directive:

#+begin_src org
,#+YOUTUBE-GT_UPDATE: https://www.youtube.com/playlist?list=PLPdNX2arS9MYUGoIp0qogtHZ3fXu46GQt
| 0  |  |  |  7:13 | 2024-01-15 | [[https://www.youtube.com/watch?v=TOg98tz6ZZM][TOg98tz6ZZM]] | Video Title Here |
| 1  |  |  | 12:45 | 2024-01-20 | [[https://www.youtube.com/watch?v=abc123][abc123]]          | Another Video    |
#+end_src

** 3. Add Manual Notes

The second and third columns are reserved for manual notes:

#+begin_src org
| 0  | watched | important |  7:13 | 2024-01-15 | [[...][...]] | Video Title |
| 1  |         | to-review | 12:45 | 2024-01-20 | [[...][...]] | Another Video |
#+end_src

These notes are *preserved* on every update, from either command.

** 4. Update Behavior

- New videos are added with their playlist positions as indices.
- Existing videos retain their manual notes.
- A row that is no longer fetched --- because it was filtered out by a
  directive parameter or removed from the playlist --- is kept in the
  table *only when it carries an annotation* in column 2 or 3.  It
  keeps the index it was last given, and the table is sorted by index,
  so it remains in the same position instead of moving to the bottom.
  Unannotated rows that are no longer fetched are removed, so
  tightening a filter deletes rows from the table rather than adding
  to it.
- A preserved row's index records where that video was positioned when
  it was last fetched.  If the playlist changes, that number can
  become inaccurate, or duplicate the index of a fetched row; the
  fetched row's index is the accurate one.
- Video metadata (title, date, duration) is refreshed on every update.

* Table Format

| Column | Description                                      | Example                   |
|--------+--------------------------------------------------+---------------------------|
| 1      | Playlist position (0-based, oldest first)        | =0=, =1=, =19999=         |
| 2      | Manual note column 1                             | =watched=                 |
| 3      | Manual note column 2                             | =important=               |
| 4      | Video duration                                   | =7:13=, =1:23:45=         |
| 5      | Publication date (ISO format)                    | =2024-01-15=              |
| 6      | Video URL (org link with video ID as label)      | =[[https://...][abc123]]= |
| 7      | Video title                                      | =Video Title Here=        |

* Configuration

** API Key

#+begin_src elisp
(setq youtube-gt-api-key "YOUR-API-KEY")
#+end_src

** Max Results Per Request

#+begin_src elisp
(setq youtube-gt-max-results 50)  ; Default: 50
#+end_src

** Directive Prefix

The line prefix scanned in each buffer.  Change it if
=#+YOUTUBE-GT_UPDATE:= collides with something else in your setup;
existing directives in your files must be renamed to match.

#+begin_src elisp
(setq youtube-gt-directive "#+YOUTUBE-GT_UPDATE")  ; Default
#+end_src

** Authinfo Lookup Coordinates

Host and login used to look up the API key in authinfo.  Change these
if your =~/.authinfo.gpg= entry uses a different machine or user name.

#+begin_src elisp
(setq youtube-gt-host-key "youtube.com")  ; Default
(setq youtube-gt-user-name "dmg")         ; Default
#+end_src

* Requirements

- Emacs 30.1+
- Internet connection for API access
- YouTube Data API v3 key

* API Quota

The YouTube Data API has a daily quota limit.  Each update operation
uses:

- 1 quota unit per 50 videos (playlistItems call)
- 1 quota unit per video details batch (videos call)

The default daily quota is 10,000 units, which is sufficient for most
use cases --- roughly one unit per 25 videos fetched.  On very large
channels, prefer =:newest= or =:since=, which stop fetching early; see
*Fetching cost* above.

* Troubleshooting

** "YouTube API key not set"

Set your API key using =M-x customize-variable youtube-gt-api-key=.

** "YouTube API error: ..."

Check that:

1. Your API key is valid
2. YouTube Data API v3 is enabled in your Google Cloud project
3. You haven't exceeded your API quota
4. The playlist URL is correct and the playlist is public

** Table not updating

Ensure:

1. You're running the command in an org-mode buffer
2. The =#+YOUTUBE-GT_UPDATE:= line has a valid playlist URL
3. Your internet connection is working
